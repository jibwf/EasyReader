# E-link 墨水屏架构文档

更新时间：2026-06-11

## 文档目的

这份文档只负责墨水屏客户端架构，不负责阶段状态、已完成功能盘点和下一步排期；阶段信息统一放在 `docs/phase1.md`。

## 产品定位

`e-link-client` 不是服务端管理界面的缩小版，而是 EasyReader 在墨水屏设备上的专用阅读终端。它的目标是：

- 阅读优先。
- 本地优先。
- 低刷新、低干扰、低功耗。
- 联网能力只服务于阅读主线。

在系统分工里：

- 服务端负责共享内容、共享状态和后台任务。
- 墨水屏客户端负责本地阅读运行时、设备交互和本地缓存生命周期。

## 架构原则

- 阅读路径本地优先：已缓存章节必须在离线场景稳定可读。
- 联网行为显式受控：WiFi 不可用时不做隐式联网。
- 状态收敛：同步和待补传状态按书收敛，不保存过时的中间轨迹。
- 设备适配本地化：刷新模式、实体按键、热区、字体都由客户端本地决策。
- 视觉规则墨水化：全局禁用阴影和高程，避免出现类 LCD 的浮层视觉噪声。
- UI 静态优先：减少动画、减少高频重绘、减少长链路前台阻塞。

## 当前已落地的收口点

### 1. 契约与同步

- `data/network/NetworkModule.kt` 已统一注入 `X-Client-Type`、`X-Client-Version`、`X-API-Contract-Version`。
- `data/model/ApiModels.kt` 已显式接住 `accepted`、`conflict`、`conflict_reason`，并支持 `force=true`。
- 阅读进度按 `book_key` 收敛；本地会保存最后阅读章节与章节内位置，而不是长期固定 `position=0.0`。
- 当服务端返回冲突时，客户端进入显式冲突处理，而不是把冲突吞成成功同步。

### 2. 离线任务与本地缓存

- `data/network/EasyReaderApi.kt`、`data/repository/ReaderRepository.kt` 已分离 `/api/offline/tasks` 与 `/api/offline/catalog`。
- `data/offline/OfflineDownloadManager.kt` 已把“服务端缓存阶段”和“设备本地落盘阶段”拆成两个连续阶段。
- `ui/EinkUiState.kt` 分别维护服务端任务状态、本地落盘状态和离线目录摘要。
- `ui/components/BookshelfPane.kt` 与 `ui/components/SettingsPane.kt` 会区分展示“服务器离线任务”和“服务器离线目录”。

### 3. 阅读器与设备交互

- 阅读器保持只读本地缓存章节；未缓存章节会展示显式入口，允许返回目录或触发本地缓存更新。
- `ui/components/ReaderPane.kt` 会恢复并回写章节内滚动位置。
- `MainActivity.kt` 已把实体翻页按键路由到 `ui/EinkViewModel.kt`。
- 自动翻页、阅读器可见性和刷新策略已经接入统一状态机。

## 分层架构

当前墨水屏客户端可以按五层理解：

### 1. 界面与交互层

- `ui/MainScreen.kt` 负责整体导航、阅读器可见性与主要页面容器。
- `ui/components/ReaderPane.kt` 负责阅读器、目录、自动翻页、未缓存章节入口和章节内位置更新。
- `ui/components/BookshelfPane.kt`、`ui/components/SearchPane.kt`、`ui/components/SettingsPane.kt` 分别负责书架、搜索、任务/同步状态与设置入口。

这一层只处理设备侧展示和交互，不直接承担网络或缓存语义。

### 2. 状态与策略层

- `ui/EinkViewModel.kt` 维护客户端主状态机。
- `ui/EinkUiState.kt` 定义阅读状态、同步冲突状态、服务端离线任务状态、本地落盘状态和设备命令状态。
- `ui/SyncPolicy.kt` 定义同步节流、补传与触发策略。

这一层负责把阅读、同步、离线任务和设备状态串成可预测的客户端行为。

### 3. 数据访问层

- `data/repository/ReaderRepository.kt` 统一封装服务端 API、本地缓存和下载流程。
- `data/offline/OfflineDownloadManager.kt` 负责“服务端任务完成后再本地落盘”的离线流程编排。

这一层的职责是“向上提供稳定数据接口”，而不是让 UI 直接感知网络协议和文件存储细节。

### 4. 本地存储与缓存层

- `data/local/LocalCacheStore.kt` 负责本地书架、目录索引、章节缓存、字体文件和缓存统计。
- 本地缓存按 `book_key` 收敛书籍与章节身份，并持久化最后阅读章节和章节内位置。

这一层决定设备在离线场景下还能继续读什么、还能恢复到哪里。

### 5. 网络与设备集成层

- `data/network/NetworkModule.kt` 和 `EasyReaderApi.kt` 负责 HTTP、契约头和 API 映射。
- `core/NetworkGate.kt` 和 `core/WifiConnectivityMonitor.kt` 负责 WiFi 闸门与网络状态。
- `core/EinkRefreshPolicy.kt`、`core/EinkDeviceRefreshBridge.kt` 负责刷新模式与设备桥接。
- `core/DeviceIdProvider.kt` 负责设备标识。

这一层统一处理“什么时候能联网、如何联网、如何适配设备”。

## 核心运行链路

### 本地阅读链路

1. 用户从本地书架、离线目录或服务端书架进入书籍。
2. 客户端优先从本地书架状态恢复最后阅读章节和章节内位置。
3. 阅读器从本地目录索引定位章节，并优先读取本地缓存正文。
4. 如果章节未缓存，阅读器只显示显式入口，不在阅读路径里偷偷拉取远端正文。
5. 阅读位置、最后阅读章节和本地状态由客户端自己维护，并在适当时机进入待补传队列。

这个链路的目标是保证“进入阅读即稳定可读”，而不是保证“阅读中永远在线”。

### 进度同步链路

1. 客户端本地维护阅读状态与待补传队列。
2. 队列按书收敛，只保留一本书的最后一条有效进度。
3. WiFi 可用时，客户端将收敛后的章节号与章节内位置上报到服务端。
4. 服务端返回共享 revision 和冲突状态；客户端据此更新本地状态、进入冲突处理或显式发起 `force=true` 覆盖。

这个链路的核心是“同步收敛”，不是“实时镜像”。

### 离线任务链路

1. 客户端显式触发离线缓存动作。
2. 服务端创建或复用后台任务并提供状态读取接口。
3. 客户端轮询任务状态，等待服务端缓存阶段完成。
4. 服务端阶段完成后，客户端再把章节落到本地缓存，并用独立状态展示本地落盘进度。
5. 任务列表与离线目录摘要分别展示，不再混成一个笼统的“下载中”。

### 设备交互链路

- 自动翻页依赖阅读器本地状态和刷新策略。
- 实体按键、触控热区、菜单打开、目录跳转都属于设备交互层，不回传给服务端。
- `MainActivity.kt` 负责把实体按键转换为阅读器命令，`EinkViewModel.kt` 统一决定如何执行。
- 刷新模式切换与局部刷新频率由设备层策略统一控制。

## 数据边界

| 领域 | 服务端是权威源 | 墨水屏客户端是权威源 |
| --- | --- | --- |
| 书架共享主数据 | 是 | 否 |
| 章节原始内容 | 是 | 否 |
| 服务端离线任务状态 | 是 | 否 |
| 跨端共享进度 | 是 | 否 |
| 本地章节缓存 | 否 | 是 |
| 本地阅读偏移/锚点 | 否 | 是 |
| 刷新模式、实体按键、热区 | 否 | 是 |
| 本地字体启用与回退 | 否 | 是 |

边界原则：

- 服务端不理解设备 UI 状态。
- 客户端不做书源解析和正文清洗。
- 共享状态由服务端统一；设备态由客户端统一。

## 架构约束

- 阅读路径不能依赖临时联网成功。
- 客户端不能在本地重做服务端搜索排序、去重和书源规则逻辑。
- 本地缓存结构必须围绕 `book_key` 组织。
- 待补传队列必须按书收敛，不能累积同一本书的一串历史进度。
- 同步冲突必须显式处理，不能默认吞掉。
- 服务端离线任务状态与设备本地落盘状态不能混成一个字段。
- UI 与设备能力适配要优先考虑低 RAM、弱 CPU 和墨水屏刷新成本。
- 墨水屏终端 UI 必须禁用阴影与高程：Card/Surface/Dialog/Button 使用 0 elevation，避免任何阴影视觉。

## 非目标

- 在墨水屏端实现书源规则解析。
- 在墨水屏端实现整书分页和复杂页码系统。
- 把客户端做成服务端管理后台镜像。
- 在客户端内部实现完整有声书生成链路。
